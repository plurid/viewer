# Viewer

Viewer is a macOS-first local file manager in the Plurid application family. It turns folders and read-only file previews into linked spatial planes, while letting routine browsing stay focused in a docked plane. The architecture must remain portable to Windows and Linux.

The first release serves frequent everyday file work: browse large folders, find files, compare previews, and organize local files, external disks, and mounted network folders. Double-clicking a folder navigates inside its plane; an explicit action opens a linked child. List, grid, columns, and gallery are functional views. File operations include create, rename, copy, move, duplicate, native Trash, collision decisions, cancellation, progress, and safe undo of rename/move.

Preview modules are typed, lazy-loaded, and independent of the explorer and spatial engine. The first set covers images, audio/video supported by Chromium, PDF, Markdown, code/text, JSON, CSV, ZIP/TAR/TAR.GZ, and GLB/glTF, OBJ, STL, and FBX. Office documents, ebooks, CAD/USD, and creative formats belong on the same extensible path; future modules must report support honestly rather than relabeling incompatible files as images.

Visual decisions inherit current Plurid applications: one look for the shell and engine, restrained surfaces, readable dense file rows, familiar macOS commands, clear selection and feedback. Focus rings and halos are suppressed at the user's request; keyboard navigation, the input caret and the active command remain functional. The defining interaction is opening a file beside its folder in space, then docking the relevant plane for focused work.

The window has no wordmark, tagline, plane-tab row or global shortcut footer. One contextual plane header exposes navigation, frame/dock and primary controls; path, search and secondary actions appear when needed. Its search icon toggles the search row, clearing and cancelling the query on close. Appearance belongs in a separate modeless Settings window whose dimensions stay stable across categories. Plurid's native bottom toolbar, minimap and viewcube are on by default with independent Settings toggles. Plane headers, title dragging and resize handles default on; plane backs are always visible and transform origin defaults off. Minimap activation faces the selected plane and selects its command context. New planes face the camera; linked-pair framing and docking are configurable. Opening an existing path/type reuses a plane within the originating root. The same file opened in another root has its own preview; an explicit Open another plane action creates a copy. Existing parentage and placement remain intact. Framing uses the live viewport and measured planes while preserving deliberate camera movements. Reopening preserves a usable saved view and recovers an active plane left clipped or offscreen. Explicit Consolidate repeated previews closes redundant automatic leaf previews from the same parent, preserves intentional copies and manually placed views, and supports one-step arrangement undo.

A shared command registry serves Command-K, autofocus searchable context menus, header actions, native commands and shortcuts. Commands bind the clicked target or current selection, filter by availability, and rank aliases and the last two applicable actions. Preview modules may contribute scoped commands without depending on the explorer or engine. Command-F finds files in the active folder or subtree; Copy/Move to opens a destination step.

Filename and metadata search uses a background local index, with explicit indexed locations, exclusions, pause/rebuild, filters and saved queries. Saved searches open as independent virtual root planes with the same file commands and Quick Preview. Document text indexing requires a separate folder grant, and revoking it removes stored body text. Browsing selection, filters and scroll positions survive spatial culling rather than depending on a mounted component.

Reusable actions cover batch rename, publication naming, model-assisted rename/organization and summaries. The publication template is `{year}, {authors}, {title}, {publisher}{extension}`; local EPUB/PDF metadata and bounded extraction supply evidence, with macOS OCR for scanned PDFs. Missing fields stay unresolved. Users review editable proposals and choose rows before any file change, with guarded Undo and interrupted-task recovery. Recipes are available through contextual commands, native menus and configurable shortcuts. Models can be OpenAI, Anthropic or a compatible local endpoint; keys stay in protected desktop storage, and sending document text requires an explicit provider permission. Opt-in MCP grants folder access and can create proposals, read metadata and search; agents cannot apply changes, trash or delete files. No cloud model is enabled automatically.

Sidebar sections fold and reorder; Locations and Favorites support shortcut arrangement, alias names and hiding. Recent remains chronological and can supply Favorites. Folder planes show the shared navigation component by default, with a direct header toggle, independent visibility/width and actions scoped to their owner. Shortcut order, aliases, Favorites and folding stay shared. Sidebar resizing works under spatial zoom and perspective and leaves file content visible in narrow planes. Window navigation starts hidden and remains independently available. Settings can change navigation defaults for later new planes. These changes alter navigation preferences only. Workspace deletion removes layout only, confirms the name and plane count, offers session recovery, and preserves files and running jobs. An operations control appears only for pending work, conflicts or unseen failures; past jobs are available through Commands and the native menu.

The workspace plus button, Command-N, Commands, the native File menu and folder actions create a fresh independent root folder plane. It starts at the active folder, the active preview’s parent or Home, with its own history and selection. Sidebar shortcuts also offer Open in new root plane. Existing roots and linked children remain intact.

Local persistence is new, versioned, and atomic. UI version 3 enables navigation in existing folder planes and hides window navigation once, after backing up the original layout metadata. Later visibility choices persist. Legacy code and ~/.viewer data stay untouched. Remote/cloud accounts, third-party plugin installation, file editing inside previews, release certificate signing, notarization, and publishing are outside this first implementation. macOS development bundles use local ad-hoc signatures so they can run on Apple Silicon.

Confirmed by the user during the planning interview and subsequent interface review; implementation authorized with “Implement the plan.” Existing files and folders must not be deleted during this work.

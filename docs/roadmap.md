This implementation establishes independent roots, shared selection/navigation, source-anchored previews, searchable Settings, native application choices, explicit folder-size measurement, an indexed search service and reviewed action recipes. The feature inventory below records gaps in this codebase, not a claim of Finder, Explorer, Dolphin or Everything parity.

## Capabilities that make the product distinctive

The goal is a coordinated file-management system whose commands, previews, search and automation share context. Each capability should have a typed service boundary, a cancellable workload, contextual commands and a useful recovery path.

| Capability                            | Intended experience                                                                                                                                                       | Required foundation                                                                                                                                                                                              |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unified typed file actions            | The same action is callable from contextual search, Command-K, shortcuts, a recipe or a scoped agent. Discovery exposes target types, inputs, outputs and availability.   | Deepen the existing UI registry and planner into a stable domain action catalog; adapters must use the same operation/proposal services.                                                                         |
| Personal publication recipes          | Select PDFs/EPUBs or a folder and trigger the saved format `year, author, title, publisher`; show extracted evidence, editable proposed names and ambiguity before Apply. | Current recipes/extraction/review, plus a representative book corpus, edition confidence, multiple-author rules, missing-field policy and checked collision handling.                                            |
| Reusable automation                   | Compose extraction → classification → rename/move into saved workflows, then run them on a selection, search collection or incoming folder.                               | Versioned workflow schema, explicit input grants, dry runs, resumable tasks, budgets and audited application. Watch-triggered execution requires its own opt-in.                                                 |
| Explainable intelligent search        | Ask for a book, topic or document; combine instant filename filters with optional semantic/content search and show which file passages support results.                   | Bounded local index, explicit content permissions, evidence-backed snippets and separately measured filename/content/semantic latency.                                                                           |
| Persistent collections                | Keep project/book/media sets from saved queries, tags or explicit membership without copying the files; open a collection as a root plane.                                | Stable identities, live query subscriptions and predictable handling of renamed, moved and offline entries.                                                                                                      |

No automatic deletion.                                                                                         |
| Spatial relationships worth using     | Keep a file beside its source, compare multiple previews, name/save arrangements and return to the same readable context.                                                 | Current source anchoring/root ownership, plus durable module state, paired docking, stable source links and measured many-plane performance.                                                                     |
| Rich modular previews                 | Inspect CAD/3D scenes, office documents, archives, media and data with type-specific commands and bounded resource use.                                                   | Existing registry/capability contracts, worker-friendly parsing, decoded-memory budgets and isolated adapters rather than a monolithic viewer.                                                                   |

## Delivery order

1. Finish and retain the reliability regressions: ownership, keyboard context, source anchoring, background verification and honest metadata/recovery. Continue performance work against recorded cold and many-preview workloads.
2. Close P1 baseline gaps through shared commands and desktop adapters, beginning with native clipboard/drag, presentation/selection and operation/volume recovery.
3. Deepen publication recipes using a varied evaluation corpus, then build reusable workflows on the shared action catalog and scoped agent interfaces.
4. Add collections, comparison, duplicate intelligence and richer preview modules as independent capabilities with explicit resource budgets.

The remaining jagginess work should follow recorded interactions and traces. Earlier menu hover scrolling, quadratic selection, unnecessary job snapshots and a file-finder render loop were specific defects. Bounded local samples do not prove that every camera gesture, mount, archive, decoder or large document is responsive. Keep a repeatable workload and compare frame times, long tasks, React commits, IPC and decoded/GPU memory before changing architecture further. Routine functional checks stay in the background; a physical compositor measurement is a separately requested foreground session.

For the publication recipe, build an evaluation corpus with varied EPUB metadata, scanned PDFs, edited editions, multiple authors and ambiguous publishers. Keep unresolved proposals unchecked. The preferred template should remain a recipe rather than a special case in the explorer. Keep agent commands on the same action/proposal services and explicit user review or execution-grant boundary.

## Implemented foundations in this increment

Finder input now has one owner before camera shortcuts, including Command-Down/Up, view shortcuts, list disclosure and column traversal. Shared folder presentation and independent local sessions have separate modules. JSONC configuration, custom commands, reviewed agent command/configuration proposals and external/embedded terminal adapters are implemented and documented. These close the corresponding foundation gaps above; they do not establish complete Finder/Explorer parity or prove physical-frame smoothness.

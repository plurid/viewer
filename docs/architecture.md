# Architecture

The active application is `packages/viewer-electron/app`. `old_app` is an archival reference and is excluded from the workspace and builds.

`src/domain` owns serializable file, operation, preview, and workspace contracts. It has no Electron or React dependencies. `src/desktop` implements filesystem access, resource capabilities, shared watchers, cancellable search, transfer jobs, and atomic persistence. `src/preload.ts` exposes a fixed typed bridge; the sandboxed renderer never imports Node or Electron. Each IPC method validates its arguments, origin and sending main frame. Arbitrary channels, remote navigation and renderer network access are unavailable.

`src/renderer/explorer` owns navigation, path-based selection, virtualized views, shared folder subscriptions and file commands. `src/renderer/workspace` adapts host pane records to Plurid routes and handles. Engine arrangement state is independent of file state. A synchronous memory storage adapter is hydrated before Plurid mounts and mirrored through the main process. Workspace switches and orderly shutdown flush both layers. Closing a parent removes its linked host branch; bounded in-memory records permit arrangement undo and redo. The active pane is restored separately in each workspace.

`src/renderer/previews` owns the preview registry and modules. A preview receives an opaque, scoped resource handle and bounded read/stream methods. Heavy viewers are loaded only when needed. A module cannot reach into explorer or engine state. Local companion assets resolve inside the model's directory scope. The resource protocol rejects traversal and escaping symlinks, uses descriptor-based streams and refuses special files. Resource responses have a sandbox CSP and never render executable documents. See [preview-modules.md](preview-modules.md) for the extension contract and resource ownership.

File commands become serial jobs in the desktop process. Collisions wait for a decision; replacements go to native Trash. Transfers preserve symlinks, stage writes, publish exclusively, support cancellation, and report completed and failed items separately. Cross-volume moves validate the source tree again before removing it. A macOS metadata adapter refuses destructive copying moves with unsupported extended attributes or ACLs. Copies currently preserve contents, POSIX modes and modification times; full Finder metadata preservation is future adapter work. Undo is limited to same-volume rename/move whose destination still matches its recorded identity, size and modification time; arrangement undo belongs to the engine.

## Plurid integration

The implementation was informed by the sibling `technologies/tools/plurid` source and current application patterns in `applications/dechat`. Viewer uses the direct named `PluridApplication`, typed public handles and the spawn-plane topic, rather than carrying the legacy renderer’s filesystem strategies and state into the engine. Plurid React `0.0.0-40` and its data/engine graph are pinned in the root lockfile. The sibling source is newer than that published release; its `tree.spawn` return type differs, so linked creation uses `SPACE_SPAWN_PLANE` with parent identity and pair framing.

Registered routes and the `view` array retain stable identities. Live configuration sizes automatic planes to the available surface while manual resizing remains an engine concern. Workspace navigation disables the engine's shared URL docking state, so one workspace cannot restore another's plane. The shell and engine receive one dark/light look. Only the plane title is a drag handle, keeping chrome buttons independent of selection gestures; model canvases stop native bubbling before engine gesture listeners. The minimap's background passes pointer events through, with its node controls still interactive. Offscreen previews pause or dispose through engine culling, with models rendering only when dirty or animated and media pausing when inactive.

The workspace header owns frame and dock controls; the engine's duplicate floating dock rail is disabled so it cannot cover preview actions. Framing waits for the engine's debounced viewport measurement after a resize, then uses its camera handle. The engine’s internal state is read only where the public seam does not expose grab/transform state or that viewport readiness. Host filesystem records, selections, jobs, resources and preferences stay in their own store. Browser storage is not the persisted source of truth.

## Verification

`tests/*.test.ts` exercise real temporary filesystem paths, partial failures, cancellation, collisions, source/destination races, cross-device and unsupported-hard-link fallback, safe undo, scoped range streams, corrupt archives, ZIP CRC/TAR checksums, PAX Unicode paths, shared watchers, streamed search and atomic state recovery. Workspace tests validate host records across engine-history reconciliation and adapter flushes.

`tests/electron-smoke.ts` launches the actual locally signed app against synthetic files in a temporary profile. It verifies every initial preview family, malformed/missing assets, selectable PDF text/search, media cleanup, four explorer views, independent model orbiting, native IPC/resource restrictions, workspace switching/restoration and the close-flush handshake. The browser fixture server adds UI checks with an isolated clipboard and Trash adapter. Raster/video fixtures are authored color samples; all model, PDF and archive fixtures are generated locally. No user files are mutated by verification.

Run `pnpm check`, `pnpm lint`, `pnpm test`, and `pnpm package` from the root. `pnpm make` produces a macOS ZIP; `pnpm test:desktop` verifies the packaged app. Fuses disable RunAsNode, Node options and Node CLI inspection, require ASAR-only loading and validate ASAR integrity. Local ad-hoc signing makes the development bundle executable; certificate signing/notarization are release work.

Actual disconnected/reconnected external drives and network mounts, release distribution, Windows and Linux remain unverified. Mounted-path behavior uses ordinary local filesystem APIs, with platform-specific Trash, dialogs, clipboard and metadata kept in desktop adapters. Format and workload limits are listed in the project README. [verification.md](verification.md) records the checks and their scope.

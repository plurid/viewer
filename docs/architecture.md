# Architecture

The active application is `packages/viewer-electron/app`. `old_app` is an archival reference and is excluded from the workspace and builds.

`src/domain` owns serializable file, operation, preview, and workspace contracts. It has no Electron or React dependencies. `src/desktop` implements filesystem access, resource capabilities, shared watchers, cancellable search, transfer jobs, and atomic persistence. `src/preload.ts` exposes a fixed typed bridge; the sandboxed renderer never imports Node or Electron. Each IPC method validates its arguments, origin and sending main frame. Arbitrary channels, remote navigation and renderer network access are unavailable.

`src/renderer/explorer` owns navigation, path-based selection, virtualized views and shared folder subscriptions. `src/renderer/commands` owns the typed registry, availability, ranking, command palette and destination step. Folder sources supply current selection and directory; window sources supply navigation, workspace and application commands. Searchable context menus capture the clicked target or multiselection. Invocation rechecks source lifetime and availability, retains the captured targets, and refreshes clipboard/jobs and live folder preferences. Recent command IDs persist without targets; the first two applicable actions are promoted without duplicate rows. Text-focused native Edit commands use a narrow preload method instead of file actions.

`src/renderer/workspace` adapts host pane records to Plurid routes and handles. Engine arrangement state is independent of file state. A synchronous memory storage adapter is hydrated before Plurid mounts and mirrored through the main process. Workspace switches and orderly shutdown flush both layers. Closing a parent removes its linked host branch; bounded in-memory records permit arrangement undo and redo. The active pane is restored separately in each workspace. Workspace deletion calls no filesystem service: it removes only the saved workspace and its adapter, retains one session recovery record, and creates an empty replacement when necessary. Jobs remain window-wide. Recovery preserves any work added to the replacement.

Optional `SavedState.ui` preferences have their own version (3), independent of core saved-state version 2. Core version 1 is read and backed up before its additive migration to version 2, which supports virtual search roots. Whole-state migration runs before UI normalization: older layouts enable each existing folder sidebar, retain its width and hide window navigation once. Storage creates an exclusive, synced, mode-0600 metadata backup before returning the migrated state; backup failures propagate without corrupt-state recovery or replacement of a valid layout. Later version-3 visibility choices survive reload. Unversioned preferences enable the restored toolbar, minimap and viewcube once; later versioned choices are respected. Each invalid field falls back independently, so malformed optional preferences do not discard valid workspaces. Optional `FolderPane.sidebar` holds only local width/visibility. The same Sidebar component renders window and plane navigation, sharing order, aliases, Favorites and folding while retaining independent sizing and visibility. Plane headers expose navigation directly; new folder planes default to visible navigation, while the optional window sidebar defaults hidden. Pointer resizing inverts the projected sidebar rectangle once at gesture start, handling spatial zoom, rotation and perspective without layout reads during movement. Narrow planes cap navigation at half the content width. Async path resolution captures workspace and pane ownership before stat; switching the active pane cannot redirect that navigation. Sidebar drag payloads describe shortcuts and section order; they are separate from file-transfer payloads. Adding a folder to Favorites uses a read-only stat and updates saved navigation only. The operations control is derived from pending/conflicting jobs and unacknowledged failures; history is explicitly opened through Commands or the native menu.

Folder selection uses a path index and an identity index with an explicit ambiguous marker. Exact-path identity checks and unique-identity rename reconciliation are linear in the listing and selection; ambiguous replacements clear. Selected-row membership uses Sets, and sort memoization depends on sort fields rather than the whole mutable pane. Command sources cache definitions by source revision, with scoped header subscriptions. Command mode mounts no file finder, folder subscription or search hook. File mode ranks lightweight entries before constructing at most 150 result commands. Pointer hover changes the active action without scrolling; keyboard movement and query changes own menu scrolling.

`explorer/selection.ts` owns file selection independently of Plurid selection. Cursor and range anchor are separate session fields; extending and reversing a range does not infer its endpoint from selected-path order. Folder and search surfaces handle file keys in React capture before engine bubble listeners. Header range keys route to the owning file session. Editable controls, dialogs and embedded previews retain their own input. Blank file-space clicks clear cursor/anchor/selection, and background context menus capture an empty file target set.

`explorer/anchors.ts` registers virtual-view reveal callbacks by host pane ID. Opening captures the workspace/root/source before awaiting reveal, then revalidates that ownership. The public spawn topic receives the source selector; Plurid measures it inside the parent plane. The reading bridge preset opens linked children at 90.1° relative to their parent, while persisted manual arrangements remain independent. Spatial preference synchronization coalesces engine emissions into a microtask: publishing preferences reentrantly between a mode change's reducer actions could restore the previous mode.

`desktop/folder-sizes.ts` performs explicit read-only logical-size scans in its own `folder-size-worker` utility process. Starting a measurement never waits for SQLite initialization, indexing, recursive watching or document extraction. It streams directory entries, bounds metadata concurrency, shares identical running selections, limits active scans to two and retains at most 64 task snapshots. Ancestor pruning prevents selected descendants from being counted again. `lstat` counts symlink entries without traversing targets; no file contents are opened. Cancellation stops new work after any pending filesystem call returns. Worker exit terminates tracked task state instead of leaving indefinite progress. The renderer's separate scoped store immediately publishes pending progress, shares in-flight starts, handles cancellation before the native acknowledgement, reports failed starts, guards late running replies, records partial results and timestamps, and invalidates overlapping measurements after observed changes. This is not disk-allocation accounting or a filesystem snapshot.

`desktop/applications.ts` uses a packaged macOS NSWorkspace helper to discover applications compatible with all captured targets. Discovered bundles and native-picker choices are canonicalized into opaque IDs; the renderer cannot provide an executable path. Opening revalidates the registered bundle and selected paths and passes literal arguments to `/usr/bin/open`, in bounded batches. The searchable fixed-height dialog retains captured targets through discovery and launch, and has loading, empty, disabled, failure and cancellation states. Non-macOS discovery reports unsupported until a native adapter exists. It changes no default association.

`src/renderer/previews` owns the preview registry and modules. A preview receives an opaque, scoped resource handle and bounded read/stream methods. Heavy viewers are loaded only when needed. A module cannot reach into explorer or engine state. Quick Preview supplies one footer through the host's render slot, combining metadata, file navigation and open actions without a second external-open icon. Its default-open control resolves the native application name only when mounted; a small, short-lived cache shares discovery. Opening still uses the live OS association. Local companion assets resolve inside the model's directory scope. The resource protocol rejects traversal and escaping symlinks, uses descriptor-based streams and refuses special files. Resource responses have a sandbox CSP and never render executable documents. EPUB uses bounded local extraction and a sanitized reader; image grids request bounded native thumbnails instead of decoding every original. See [preview-modules.md](preview-modules.md) for the extension contract and resource ownership.

File commands become serial jobs in the desktop process. Selected ancestors prune descendants through Set membership and path-parent walking while retaining source order and path boundaries. Progress is throttled across the entire job at 80 ms, including between small files. Sequenced `job-progress` events carry counters, current path and error count; queued/running, collision/resolution, terminal and undo transitions send complete authoritative jobs. The renderer rejects stale revisions and resynchronizes unknown jobs or sequence gaps through the jobs endpoint, retaining full completed/error inventories. Collisions wait for a decision; replacements go to native Trash. Transfers preserve symlinks, stage writes, publish exclusively, support cancellation, and report completed and failed items separately. Cross-volume moves validate the source tree again before removing it. A macOS metadata adapter refuses destructive copying moves with unsupported extended attributes or ACLs. Copies currently preserve contents, POSIX modes and modification times; full Finder metadata preservation is future adapter work. Undo is limited to same-volume rename/move whose destination still matches its recorded identity, size and modification time; arrangement undo belongs to the engine.

## Plurid integration

The implementation was informed by the sibling `technologies/tools/plurid` source and application patterns in `applications/containers/plurid-com/frontends/web/products/cores/dechat`. Viewer uses the direct named `PluridApplication`, typed public handles and the spawn-plane topic. Plurid React `0.0.0-40` and its data/engine graph are pinned in the root lockfile. The sibling source is newer than that published release; its `tree.spawn` return type differs, so linked creation uses `SPACE_SPAWN_PLANE` with parent identity and host-owned framing.

Registered routes and the `view` array retain stable identities. `WorkspaceController.newRootFolder` synchronously reserves a fresh host folder/root, copies the originating folder’s view preferences and initializes independent history. The declarative root list merges additions with the live engine tree; no second imperative view mutation races React or duplicates a root. Captured workspace/pane ownership rejects stale invocations. Window plus, Command-N, Commands, native menu, plane actions and shortcut actions share this path. Live configuration sizes automatic planes to the available surface while manual resizing remains an engine concern. A host preference subscription reconciles restored engine configuration with current UI preferences, including deferred measured-tree hydration. Workspace navigation disables the engine's shared URL docking state, so one workspace cannot restore another's plane. The shell and engine receive one dark/light look. Only the plane title is a drag handle: its capture handler selects an unselected plane before the engine's gesture listener, so the first press moves that plane; an already selected plane preserves multiselection. Chrome buttons and content retain their own gestures. Model canvases isolate gesture initiation from engine controls while allowing move/up events to reach Three's document listeners. Plane backs are always visible; title dragging, headers and resizing default on. Native minimap navigation uses single-plane framing even for linked children, and its click capture binds the host active pane without issuing a competing camera tween. Restored engine configuration cannot override these two invariants. The native toolbar, minimap and viewcube default on with independent Settings switches; transform origin defaults off. Transform commands read and publish the engine's mode, shared with the native toolbar and Escape. Offscreen previews pause or dispose through engine culling, with models rendering only when dirty or animated and media pausing when inactive.

One contextual plane header exposes navigation, view, search and frame/dock; narrower headers keep spatial actions in the registry. There is no global plane-tab toolbar or footer. Preview controls use a host-supplied header slot; the engine's duplicate dock rail and palette are disabled. Normal opening reuses a normalized path/type within the originating root, using live tree ownership plus pending spawn reservations, synchronously reserving host records to make rapid repeat events idempotent. Existing links and positions are retained; explicit Open another plane bypasses reuse. Saved duplicate records are preserved until explicit recovery. `Consolidate repeated previews` closes only automatic leaf previews with the same normalized path and parent, excluding manually positioned views, shared host IDs and `PreviewPane.keepSeparate` copies. Exported engine history grouping actions make the edit one undo step; bounded closed host records restore both layers on undo. New planes use single-plane `camera.frame` by default, giving a face-on view; Settings may choose linked-pair framing or docking. Framing waits for resolved engine layout, the public inspected viewport to match the surface, and live DOM plane measurements to match stable engine boxes. It uses `camera.frame`, `camera.fit` or the public multi-plane frame topic. Resize refits only the camera position last owned by that framing request; manual movement cancels ownership. Restoration uses the same measured readiness check, keeping a fully visible active plane's saved camera verbatim and framing only a clipped/offscreen active plane. Plane locations also participate in the settling signature. Public inspection/snapshot seams supply viewport, grab and transform state. Host filesystem records, selections, jobs, resources and preferences stay in their own store. Browser storage is not the persisted source of truth.

Preview modules receive an optional command capability with `register()` and a header element. Commands have stable module-local IDs, availability and handlers; the host adds preview scope, resource/pane lifetime checks and cleanup. `PreviewToolbar` uses the header slot in a spatial plane and an inline toolbar in quick previews. Modules do not import the registry, explorer or engine.

## Service boundaries

`SettingsService` is the authoritative revisioned preference document shared by the Viewer and modeless Settings windows. Patches merge independent field edits and reject stale overlapping edits. Renderer writes are serialized; native close/quit asks Settings to commit its focused field and drain queued writes before flushing metadata. The Settings IPC role cannot invoke file mutations or read file resources.

Native Quit shares the in-flight window save handshake and keeps the IPC bridge alive until Electron closes all windows. Service disposal starts in `will-quit`, with guards against activation, second-instance events or Settings reopening during shutdown. Native window Close saves without disposing services, allowing macOS activation to reopen Viewer. Disposal is idempotent and waits for every service's cleanup, including journaled file mutations. Each read-only utility worker's shutdown rejects pending reads, allows two seconds for its index/cache checkpoint or scan cancellation, then bounds termination to one additional second. Only those owned workers may be force-stopped; source-file mutations and state writes are drained without a forced timeout.

`FileServices` owns independent restartable indexing and folder-size utility processes through `UtilityClient` until terminal shutdown; late calls cannot restart either after service disposal. `index-core.ts` implements SQLite/WAL with FTS5 trigram filename/document-text search and bounded result pages. Worker configuration, crawling, shared watching, document extraction and cancellation stay outside the renderer. Content-grant revocation clears stored text immediately; generation checks discard late extraction. `formats.ts` handles bounded PDF/EPUB/plain-text evidence and the packaged local macOS OCR helper. Search roots and exclusions are rechecked at query time, including cached/offline records. `SearchExplorer` is a virtual root using the same file commands, dialogs, recipes and preview ownership as a physical folder.

`ActionPlanner` captures `ActionContext` and creates typed proposals using local transformations or provider output. Provider output is validated against source IDs, paths and evidence before review. Apply requires an exact revision and explicit rows, uses the ordinary operations lock, checks sources again, journals transition intent and publishes exclusively. Safe Undo and recovery are separate reviewed transactions. Summary input identities survive restart and are rechecked before export/application. Actions expose progress through bounded snapshots; reviewed rows are virtualized.

`providers.ts` adapts OpenAI, Anthropic and compatible local endpoints behind one structured proposal interface. Keys use Electron secure storage only on explicit credential storage/use. `AgentBroker` uses an app-owned mode-0600 local token without Keychain, canonical folder grants and proposal-only MCP tools. Its socket is mode 0600 in a private temporary directory. `mcp-client.ts` implements the packaged executable's headless stdio client; the UI process remains the service and approval owner.

`workspace/sessions.ts` keeps selection, filtering, anchors, cached entries and scroll outside culled React components. Shared folder data has one watch/load subscription per normalized path, bounded idle caching and coalesced refreshes. File-change batches apply a simultaneous longest-ancestor path map to panes, histories, navigation and sessions, preserving rename cycles and path boundaries. Preview state keys use host/resource identity for image pan/zoom, PDF page/zoom and model wireframe. Model cameras, media position and every module's state are not yet durable across culling.

These services are in-repository extension points; they are not a third-party plugin sandbox. [actions.md](actions.md) and [search.md](search.md) document their permissions, limits and user flows.

## Verification scope

`tests/*.test.ts` exercise real temporary filesystem paths, partial failures, cancellation, collisions, source/destination races, cross-device and unsupported-hard-link fallback, safe undo, scoped range streams, corrupt archives, ZIP CRC/TAR checksums, PAX Unicode paths, shared watchers, streamed search and atomic state recovery. Command tests use mocked services to check availability, target snapshots, alias/recency ranking, stale sources, clipboard and text editing. State tests verify layout-only deletion/recovery, jobs, sidebar preferences and legacy state. Workspace tests validate host records across engine-history reconciliation and adapter flushes.

`tests/electron-smoke.ts` launches the actual locally signed app against synthetic files in a temporary profile. It verifies every initial preview family, malformed/missing assets, selectable PDF text/search, media cleanup, four explorer views, independent model orbiting, native IPC/resource restrictions, workspace switching/restoration and the close-flush handshake. The browser fixture server adds UI checks with an isolated clipboard and Trash adapter. Raster/video fixtures are authored color samples; all model, PDF and archive fixtures are generated locally. No user files are mutated by verification.

Packaged functional checks default to hidden offscreen Viewer and Settings windows with GPU rendering retained. Test mode requires explicit render/background flags and an isolated profile; normal window behavior is unaffected. The macOS QA instance uses accessory activation policy and never calls window show/focus or native activation. A read-only NSRunningApplication probe asserts that it remains inactive, including after closing Settings. Foreground activation and physical frame profiling require `VIEWER_TEST_FOREGROUND=1`; offscreen timings are excluded from those measurements.

Run `pnpm check`, `pnpm lint`, `pnpm test`, and `pnpm package` from the root. `pnpm make` produces a macOS ZIP; `pnpm test:desktop` verifies the packaged app. Fuses disable RunAsNode, Node options and Node CLI inspection, require ASAR-only loading and validate ASAR integrity. Local ad-hoc signing makes the development bundle executable; certificate signing/notarization are release work.

Actual disconnected/reconnected external drives and network mounts, release distribution, Windows and Linux remain unverified. Mounted-path behavior uses ordinary local filesystem APIs, with platform-specific Trash, dialogs, clipboard and metadata kept in desktop adapters. Format and workload limits are listed in the project README. [verification.md](verification.md) records the checks and their scope; [performance.md](performance.md) records measured workloads and remaining performance risks.

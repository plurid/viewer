# Architecture

The active application is `packages/viewer-electron/app`. `old_app` is an archival reference and is excluded from the workspace and builds.

`src/domain` owns serializable file, operation, preview, and workspace contracts. It has no Electron or React dependencies. `src/desktop` implements filesystem access, resource capabilities, shared watchers, cancellable search, transfer jobs, and atomic persistence. `src/preload.ts` exposes a fixed typed bridge; the sandboxed renderer never imports Node or Electron. Each IPC method validates its arguments, origin and sending main frame. Arbitrary channels, remote navigation and renderer network access are unavailable.

`src/renderer/explorer` owns navigation, path-based selection, virtualized views and shared folder subscriptions. `src/renderer/commands` owns the typed registry, availability, ranking, command palette and destination step. Folder sources supply current selection and directory; window sources supply navigation, workspace and application commands. Searchable context menus capture the clicked target or multiselection. Invocation rechecks source lifetime and availability, retains the captured targets, and refreshes clipboard/jobs and live folder preferences. Recent command IDs persist without targets; the first two applicable actions are promoted without duplicate rows. Text-focused native Edit commands use a narrow preload method instead of file actions.

`src/renderer/workspace` adapts host pane records to Plurid routes and handles. Engine arrangement state is independent of file state. A synchronous memory storage adapter is hydrated before Plurid mounts and mirrored through the main process. Workspace switches and orderly shutdown flush both layers. Closing a parent removes its linked host branch; bounded in-memory records permit arrangement undo and redo. The active pane is restored separately in each workspace. Workspace deletion calls no filesystem service: it removes only the saved workspace and its adapter, retains one session recovery record, and creates an empty replacement when necessary. Jobs remain window-wide. Recovery preserves any work added to the replacement.

Optional `SavedState.ui` preferences have their own version (3), independent of core saved-state version 1. Whole-state migration runs before UI normalization: older layouts enable each existing folder sidebar, retain its width and hide window navigation once. Storage creates an exclusive, synced, mode-0600 metadata backup before returning the migrated state; backup failures propagate without corrupt-state recovery or replacement of a valid layout. Later version-3 visibility choices survive reload. Unversioned preferences enable the restored toolbar, minimap and viewcube once; later versioned choices are respected. Each invalid field falls back independently, so malformed optional preferences do not discard valid workspaces. Optional `FolderPane.sidebar` holds only local width/visibility. The same Sidebar component renders window and plane navigation, sharing order, aliases, Favorites and folding while retaining independent sizing and visibility. Plane headers expose navigation directly; new folder planes default to visible navigation, while the optional window sidebar defaults hidden. Pointer resizing inverts the projected sidebar rectangle once at gesture start, handling spatial zoom, rotation and perspective without layout reads during movement. Narrow planes cap navigation at half the content width. Async path resolution captures workspace and pane ownership before stat; switching the active pane cannot redirect that navigation. Sidebar drag payloads describe shortcuts and section order; they are separate from file-transfer payloads. Adding a folder to Favorites uses a read-only stat and updates saved navigation only. The operations control is derived from pending/conflicting jobs and unacknowledged failures; history is explicitly opened through Commands or the native menu.

Folder selection uses a path index and an identity index with an explicit ambiguous marker. Exact-path identity checks and unique-identity rename reconciliation are linear in the listing and selection; ambiguous replacements clear. Selected-row membership uses Sets, and sort memoization depends on sort fields rather than the whole mutable pane. Command mode mounts no file finder, folder subscription or search hook. File mode ranks lightweight entries before constructing at most 150 result commands. Pointer hover changes the active action without scrolling; keyboard movement and query changes own menu scrolling.

`src/renderer/previews` owns the preview registry and modules. A preview receives an opaque, scoped resource handle and bounded read/stream methods. Heavy viewers are loaded only when needed. A module cannot reach into explorer or engine state. Local companion assets resolve inside the model's directory scope. The resource protocol rejects traversal and escaping symlinks, uses descriptor-based streams and refuses special files. Resource responses have a sandbox CSP and never render executable documents. See [preview-modules.md](preview-modules.md) for the extension contract and resource ownership.

File commands become serial jobs in the desktop process. Selected ancestors prune descendants through Set membership and path-parent walking while retaining source order and path boundaries. Progress is throttled across the entire job at 80 ms, including between small files. Sequenced `job-progress` events carry counters, current path and error count; queued/running, collision/resolution, terminal and undo transitions send complete authoritative jobs. The renderer rejects stale revisions and resynchronizes unknown jobs or sequence gaps through the jobs endpoint, retaining full completed/error inventories. Collisions wait for a decision; replacements go to native Trash. Transfers preserve symlinks, stage writes, publish exclusively, support cancellation, and report completed and failed items separately. Cross-volume moves validate the source tree again before removing it. A macOS metadata adapter refuses destructive copying moves with unsupported extended attributes or ACLs. Copies currently preserve contents, POSIX modes and modification times; full Finder metadata preservation is future adapter work. Undo is limited to same-volume rename/move whose destination still matches its recorded identity, size and modification time; arrangement undo belongs to the engine.

## Plurid integration

The implementation was informed by the sibling `technologies/tools/plurid` source and application patterns in `applications/containers/plurid-com/frontends/web/products/cores/dechat`. Viewer uses the direct named `PluridApplication`, typed public handles and the spawn-plane topic. Plurid React `0.0.0-40` and its data/engine graph are pinned in the root lockfile. The sibling source is newer than that published release; its `tree.spawn` return type differs, so linked creation uses `SPACE_SPAWN_PLANE` with parent identity and host-owned framing.

Registered routes and the `view` array retain stable identities. `WorkspaceController.newRootFolder` synchronously reserves a fresh host folder/root, copies the originating folder’s view preferences and initializes independent history. The declarative root list merges additions with the live engine tree; no second imperative view mutation races React or duplicates a root. Captured workspace/pane ownership rejects stale invocations. Window plus, Command-N, Commands, native menu, plane actions and shortcut actions share this path. Live configuration sizes automatic planes to the available surface while manual resizing remains an engine concern. A host preference subscription reconciles restored engine configuration with current UI preferences, including deferred measured-tree hydration. Workspace navigation disables the engine's shared URL docking state, so one workspace cannot restore another's plane. The shell and engine receive one dark/light look. Only the plane title is a drag handle: its capture handler selects an unselected plane before the engine's gesture listener, so the first press moves that plane; an already selected plane preserves multiselection. Chrome buttons and content retain their own gestures. Model canvases isolate gesture initiation from engine controls while allowing move/up events to reach Three's document listeners. Plane backs are always visible; title dragging, headers and resizing default on. Native minimap navigation uses single-plane framing even for linked children, and its click capture binds the host active pane without issuing a competing camera tween. Restored engine configuration cannot override these two invariants. The native toolbar, minimap and viewcube default on with independent Settings switches; transform origin defaults off. Transform commands read and publish the engine's mode, shared with the native toolbar and Escape. Offscreen previews pause or dispose through engine culling, with models rendering only when dirty or animated and media pausing when inactive.

One contextual plane header exposes navigation, view, search and frame/dock; narrower headers keep spatial actions in the registry. There is no global plane-tab toolbar or footer. Preview controls use a host-supplied header slot; the engine's duplicate dock rail and palette are disabled. Normal opening reuses a normalized path/type within the current workspace, synchronously reserving host records to make rapid repeat events idempotent. Existing links and positions are retained; explicit Open another plane bypasses reuse. Saved duplicate records are preserved until explicit recovery. `Consolidate repeated previews` closes only automatic leaf previews with the same normalized path and parent, excluding manually positioned views, shared host IDs and `PreviewPane.keepSeparate` copies. Exported engine history grouping actions make the edit one undo step; bounded closed host records restore both layers on undo. New planes use single-plane `camera.frame` by default, giving a face-on view; Settings may choose linked-pair framing or docking. Framing waits for resolved engine layout, the public inspected viewport to match the surface, and live DOM plane measurements to match stable engine boxes. It uses `camera.frame`, `camera.fit` or the public multi-plane frame topic. Resize refits only the camera position last owned by that framing request; manual movement cancels ownership. Restoration uses the same measured readiness check, keeping a fully visible active plane's saved camera verbatim and framing only a clipped/offscreen active plane. Plane locations also participate in the settling signature. Public inspection/snapshot seams supply viewport, grab and transform state. Host filesystem records, selections, jobs, resources and preferences stay in their own store. Browser storage is not the persisted source of truth.

Preview modules receive an optional command capability with `register()` and a header element. Commands have stable module-local IDs, availability and handlers; the host adds preview scope, resource/pane lifetime checks and cleanup. `PreviewToolbar` uses the header slot in a spatial plane and an inline toolbar in quick previews. Modules do not import the registry, explorer or engine.

## Verification

`tests/*.test.ts` exercise real temporary filesystem paths, partial failures, cancellation, collisions, source/destination races, cross-device and unsupported-hard-link fallback, safe undo, scoped range streams, corrupt archives, ZIP CRC/TAR checksums, PAX Unicode paths, shared watchers, streamed search and atomic state recovery. Command tests use mocked services to check availability, target snapshots, alias/recency ranking, stale sources, clipboard and text editing. State tests verify layout-only deletion/recovery, jobs, sidebar preferences and legacy state. Workspace tests validate host records across engine-history reconciliation and adapter flushes.

`tests/electron-smoke.ts` launches the actual locally signed app against synthetic files in a temporary profile. It verifies every initial preview family, malformed/missing assets, selectable PDF text/search, media cleanup, four explorer views, independent model orbiting, native IPC/resource restrictions, workspace switching/restoration and the close-flush handshake. The browser fixture server adds UI checks with an isolated clipboard and Trash adapter. Raster/video fixtures are authored color samples; all model, PDF and archive fixtures are generated locally. No user files are mutated by verification.

Run `pnpm check`, `pnpm lint`, `pnpm test`, and `pnpm package` from the root. `pnpm make` produces a macOS ZIP; `pnpm test:desktop` verifies the packaged app. Fuses disable RunAsNode, Node options and Node CLI inspection, require ASAR-only loading and validate ASAR integrity. Local ad-hoc signing makes the development bundle executable; certificate signing/notarization are release work.

Actual disconnected/reconnected external drives and network mounts, release distribution, Windows and Linux remain unverified. Mounted-path behavior uses ordinary local filesystem APIs, with platform-specific Trash, dialogs, clipboard and metadata kept in desktop adapters. Format and workload limits are listed in the project README. [verification.md](verification.md) records the checks and their scope; [performance.md](performance.md) records measured workloads and remaining performance risks.

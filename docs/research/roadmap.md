# Product priorities

Viewer should remain easy for everyday work while gaining depth in the tools people already use.
This is a set of directions, not a release schedule.

## Make the existing experience dependable

Continue long-session resource audits, real-file qualification, source-change recovery and complete
workflows. Test native permissions, external disks/providers, window restoration and accessibility
in actual platform builds. Keep UI input, document lifetimes and runtime lifetimes distinct.

The current implementation already includes worktrees/tasks, hunk review, parameterized commands,
reported agent sessions, Journal and focused creative tools. Future planning must start from that
[current capability map](../reference/capabilities.md).

## Deepen everyday tools

Improve search discovery and filter editing, large-folder handling, comparison, batch metadata,
preview fidelity and richer creative operations. Treat Office font/layout differences, media codecs
and animated/multipage images as concrete coverage work. Improve a task's result rather than only
increasing extension counts.

## Expand file ecosystems

Priorities worth investigating include IFC/BIM, point clouds, DICOM, mechanical CAD interchange,
subtitles, Office variants, web archives, columnar/scientific data, molecular structures, package
inspection and robotics/simulation formats. The [format research](formats.md) retains the broader
inventory and feasibility distinctions. Decoder presence, semantic inspection and full fidelity are
separate.

## Connect work through space

Explore comparison rooms, change-review paths, semantic zoom, context receipts, conversation
branches and explicit agent adapters. Keep ordinary focused use available.
[Spatial development](spatial-development.md) describes where extra space can improve comprehension.

## Share a useful result

Explore links to local references, immutable snapshots and later live content. Show recipients a
useful view with clear access and lifetime. [Sharing](sharing.md) keeps those different service
requirements separate.

## Investigate physical workflows

Viewer Workshop could connect source documents, CAD, images and verified evidence around an assembly
or fabrication task. [The hackathon strategy](workshop.md) describes the proposed demonstration and
what must be new work.

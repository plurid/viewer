# Configuration

This page lists every field of `config.jsonc`, with its default, its allowed values and where
Settings changes it.

## The file

Settings and `config.jsonc` edit the same configuration. **Settings → Configuration** shows the
file's path and has **Open config.jsonc**, **Validate**, **Export configuration**, **Import
configuration** and **Reset a section**.

| Item                | Value                                                                                |
| ------------------- | ------------------------------------------------------------------------------------ |
| File                | `~/Library/Application Support/Viewer/config.jsonc`                                  |
| Editor schema       | `config.schema.json` in the same folder, generated by Viewer at launch               |
| Last valid copy     | `config.jsonc.last-valid` in the same folder                                         |
| Size limit          | 16 MB (16,000,000 bytes)                                                             |
| Top-level fields    | `$schema` (`"config.schema.json"`), `version` (`1`), `settings`, `ui`                |
| `ui.version`        | `4`; a `3` file is rewritten once, its plane toolbar set to Essential, comments kept |
| Syntax              | JSONC: comments and trailing commas are allowed                                      |
| Rejected            | Unknown fields, wrong types, values out of range, duplicate IDs, conflicting keys    |
| Kept, with warnings | References to a missing recipe, profile or action; the action that uses one fails    |
| Never in this file  | Credentials, model data permissions, agent grants, terminal-read grants, workspaces  |

The first write adds guide comments above documented fields. Later writes keep your comments and
formatting and add guidance only for fields that were added.

This partial example sets one folder's view:

```jsonc
{
  "version": 1,
  "settings": {
    "folders": {
      "/work/Photos": {
        "mode": "grid",
        "sort": "modified",
        "descending": true,
      },
    },
  },
}
```

Folder keys are absolute paths. `~`, environment variables and shell expressions are not expanded.

## Validation and recovery

| Situation                                          | What Viewer does                                                                                                                                                              |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A valid edit on disk                               | Reloads it live; **Recent changes** lists the changed paths                                                                                                                   |
| An invalid edit, or a `version` other than `1`     | Leaves the file on disk, shows the diagnostic and runs on the last valid copy; saving from Settings fails until the file is fixed                                             |
| Both the file and its last valid copy unreadable   | Runs on the defaults and saves nothing until `config.jsonc` is fixed                                                                                                          |
| The file removed while Viewer runs                 | Keeps the current settings, offers **Restore config.jsonc** and writes the file again with the next change                                                                    |
| The file missing at launch, its last copy valid    | Restores the file from the last valid copy and says so                                                                                                                        |
| A setting changed elsewhere since a window read it | Refuses the write: "This setting changed in another window or config.jsonc. Review its current value."                                                                        |
| **Import configuration**                           | Validates the whole file first; asks before changing agent access, model providers, program actions, terminal profiles or risky key lines                                     |
| **Reset a section**                                | Puts back the defaults of **Browsing**, **Folder views**, **File opening**, **Previews**, **Terminals**, **Custom commands**, **Shortcuts**, **Search** or **Action recipes** |

Risky key lines are bindings and sequences that type into a terminal, move files to the Trash,
rename files or close with `!` and drop unsaved text. A cancelled import changes nothing.

A workspace window may change only its own presentation: `ui`, `settings.folders`,
`settings.toolbars`, `settings.appearance`, `settings.browsing` (except `confirmTrash`),
`settings.savedSearches`, `settings.editor`, `settings.terminalFont`, `settings.tour`,
`settings.previews.darkPages`, `settings.tiling`, `settings.layouts`,
`settings.optimizationRecipes`, `settings.profiles` and `settings.theme`. Everything else changes
only in Settings or in the file.

## Units

| Quantity          | Unit                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| Sizes             | Decimal, as Finder shows them: 1 KB = 1,000 bytes, 1 MB = 1,000,000 bytes |
| `budgetBytes`     | Bytes: `5000000000` is 5 GB                                               |
| `maxModelMB`      | Megabytes of 1,000,000 bytes                                              |
| Times             | Milliseconds                                                              |
| Widths and fonts  | Pixels, except `terminalFont.lineHeight`, a multiple of the font's height |
| Image pixel limit | Decoded pixels (width × height), not bytes                                |

and logging out quit at once. `quit` and `updates` change only in Settings or the file.

## Folder views

`settings.folders` maps an absolute folder path to a sparse override; omitted fields use
`settings.browsing`. An override applies to that path in every plane, root and workspace. Selection,
history, search and scroll stay with each plane. **Settings → Browsing → Folder views** lists the
overrides, changes their view and resets them.

| Field          | Values                                                                    |
| -------------- | ------------------------------------------------------------------------- |
| `mode`         | `list`, `grid`, `columns`, `gallery`, `map`                               |
| `sort`         | `name`, `modified`, `created`, `size`, `kind`, `extension`                |
| `descending`   | Boolean                                                                   |
| `group`        | `none`, `kind`, `modified`, `lens`                                        |
| `lens`         | The UUID of the lens used when `group` is `lens`; see [lenses](lenses.md) |
| `density`      | `comfortable`, `compact`                                                  |
| `foldersFirst` | Boolean                                                                   |
| `showHidden`   | Boolean                                                                   |
| `columnWidth`  | 160 to 1600                                                               |
| `list`         | `visible`, `widths`, `order` and `wrapNames`, as in `ui.list`             |

## File opening

| Setting                        | Default                                                    | Values                                                                  | Settings label               |
| ------------------------------ | ---------------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------------- |
| `settings.fileOpening.default` | `automatic`                                                | `automatic`, `plane`, `native`                                          | **Previews → Open files in** |
| `settings.fileOpening.types`   | `doc`, `docx`, `xls`, `xlsx`, `ppt`, `pptx` set to `plane` | Lowercase extension, no dot: `plane` or `native`; at most 30 characters | None                         |

`automatic` uses an in-app preview when there is one and the system's application otherwise; `plane`
opens a linked plane; `native` opens the file in its application. **Open With…** and **Open linked

files open in planes.

`night` or `system` with that choice. Printing, **Optimize…**, **PDF tools…**, exports and saved
copies keep the document's own colours. A configuration without these fields uses the defaults.

## Tour files

A tour is a JSONC file whose name ends in `.viewer-tour.jsonc`; the part before it names the tour.
Opening it plays it. It opens files and moves the camera, and never runs commands, workflows or
model requests. A named agent client that opens one waits for your review. **Save tour** writes it
with comments; later saves keep them and refuse to replace a version someone else saved.

```jsonc
{
  "version": 1,
  "name": "Brackets",
  "stops": [
    {
      "id": "pitch",
      "caption": "The drawing asks for 48 mm between the holes",
      "source": "check",
      "finding": { "id": "pitch", "grade": "confirmed" },
      "target": {
        "kind": "file",
        "path": "Drawings/Bracket.pdf",
        "version": {
          "identity": "16777232:90210",
          "modified": 1761800000000,
          "size": 48213,
          "sha256": "9f2c5b0e7d41a3c86e1f04b2d9a7c35e8b6f10d24c7e9a5b3f8d06c1e2a4b7d9",
        },
        "anchor": {
          "kind": "pdf",
          "page": 2,
          "region": [
            [0.61, 0.7],
            [0.8, 0.7],
            [0.8, 0.79],
          ],
        },
      },
    },
  ],
}
```

| Field     | Values                                                                               |
| --------- | ------------------------------------------------------------------------------------ |
| `version` | `1`                                                                                  |
| `name`    | 1 to 100 characters                                                                  |
| `dwell`   | Optional: ms each stop shows, 0 to 600,000, or `null` to wait for **→**              |
| `stops`   | 1 to 200 stops, each `{id, caption, note?, dwell?, source, finding?, view?, target}` |

| Stop field | Values                                                                                                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`       | Letters, digits, `.`, `_` and `-`, up to 200; unique in the tour                                                                                                                                                                                      |
| `caption`  | 1 to 500 characters; `note`, shown under it, up to 4,000                                                                                                                                                                                              |
| `dwell`    | As the tour's. Without either, a stop shows long enough to read its caption and note, up to 30 s, and at least `settings.tour.dwell`                                                                                                                  |
| `source`   | `recorded`, `model` or `check`                                                                                                                                                                                                                        |
| `finding`  | `{id, grade?}`; `grade` is `confirmed`, `refuted` or `unverified`, shown on the tour bar                                                                                                                                                              |
| `view`     | `{pose?}`: `dock`, `frame` (which also leaves a docked page) or, on Plurid 0.0.0-43, Plurid's `{yaw, pitch, roll?, scale, pivot, offset?}`. The camera goes to the plane showing the stop's file; another host's `path` or `occurrence` is never used |
| `target`   | `{kind: "file", path, version, anchor?, quote?}` or `{kind: "view", bookmark}`, a saved view of the workspace that plays it                                                                                                                           |

A file target's `path` is relative to the tour file and stays inside its folder: no `..` or `.`
parts, no empty parts, no absolute or drive paths, no backslashes, and never a `.viewer-tour.jsonc`
or `viewer.project.jsonc` file, which opening would play or install. When the stop plays, every part
of the path below the tour's folder must be a folder or the file itself, never a link, and the file
must resolve inside the folder; the tour's folder itself may be reached through a link.

`version` is the file's `{identity, modified, size, sha256?}` when the stop was recorded. `sha256`,
64 lowercase hexadecimal digits, is the hash of the file's bytes: recording reads it for a file up
to 64 MiB, and a check records it for each file it read. When the stop has one, playing reads the
file's hash again (up to 64 MiB), and the bytes decide, so a copy whose date a zip moved still opens
as recorded. Without a hash on either side, a size and modification time that match (to 2 s) decide;
the identity never does, since a copy has a new one. A changed file opens as it is now, without the
`anchor` and without the mark an earlier stop left in its plane, and the tour bar says **Changed
since recorded**. A stop whose file or view is missing, reached through a link, or in a folder
Viewer may not read is skipped, and the tour bar says which.

| Anchor `kind` | Fields                                                                                                                                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pdf`         | `page`; optional `region`, `zoom` (`page`, `width`, or 0.1 to 4) and `search: false`. Without it, the `quote` lists the pages that match it; the anchored page stays                                       |
| `image`       | `x`, `y`, `width`, `height` from 0 to 1; optional `polygon` inside that box                                                                                                                                |
| `dxf`         | `entities`: IDs by position in the drawing, up to 5,000; optional `view` `{min: [x, y], max: [x, y]}` in drawing units, and `measure`: up to 20 `{tool, points}` with `tool` `distance`, `angle` or `area` |
| `model`       | `position` and `target`, each `[x, y, z]` in the model's units                                                                                                                                             |
| `text`        | `line` from 1, `start` and `end`; in an email, the plain text shows with the line of the match marked: where the line moved, the `quote` places it, read from `start` less up to 90 characters             |
| `epub`        | `chapter` from 0                                                                                                                                                                                           |
| `document`    | `block` from 0                                                                                                                                                                                             |
| `cells`       | `sheet?`, `row` and `column` from 1                                                                                                                                                                        |
| `media`       | `seconds`                                                                                                                                                                                                  |

A `region` or `polygon` is 3 to 512 points `[x, y]`, from 0 to 1 across and down the page or picture
as shown. A PDF region without its own `zoom`, a small image region and a DXF focus are each
enlarged to fill about 60% of the view. Outlines draw in once the camera is at rest at their stop.

## Search

Shown in **Settings → Search**. Query syntax is in [search](search.md).

| Setting                        | Default                         | Values                                                     | Settings label                |
| ------------------------------ | ------------------------------- | ---------------------------------------------------------- | ----------------------------- |
| `settings.search.roots`        | Your Home folder                | Up to 100 absolute folders, indexed with their subfolders  | **Indexed locations**         |
| `settings.search.exclusions`   | `~/Library` and the names below | Up to 200 absolute paths or bare names                     | **Excluded names and paths**  |
| `settings.search.contentRoots` | `[]`                            | Up to 100 absolute folders whose document text is indexed  | **Indexed locations**         |
| `settings.search.paused`       | `false`                         | Boolean                                                    | **Pause background indexing** |
| `settings.savedSearches`       | `[]`                            | Up to 100 `{id, name, query, root?, recursive?, content?}` | **Saved searches**            |

An absolute exclusion leaves out its subtree; a bare name leaves out every path component with that
name. They are not glob patterns. The default names are `.git`, `node_modules`, `.venv`, `venv`,
`__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `.nox`, `.cache`, `.vite`,
`.next`, `.nuxt`, `.svelte-kit`, `.turbo`, `.parcel-cache`, `.pnpm-store`, `.yarn`, `.gradle`,
`target` and `out`. An empty `contentRoots` turns document-text indexing off; removing a root
removes its indexed text. Indexing text never allows sending it to a model. A saved search's `query`
is up to 1,000 characters, as any query is, and its `name` up to 100; omit `root` to search every
indexed location.

## Models and recipes

Shown in **Settings → Models** and **Settings → Actions**. Model use is described in
[agents](agents.md#add-a-model).

| Setting                        | Default                   | Values                                                                             |
| ------------------------------ | ------------------------- | ---------------------------------------------------------------------------------- |
| `settings.providers`           | `[]`                      | Up to 20 `{id, name, kind, endpoint, model, allowContent, effort?, segmentation?}` |
| `settings.prompts.providerID`  | `""` (the first provider) | A provider ID; the model behind `>` prompts and Ask Viewer                         |
| `settings.recipes`             | The five built-in recipes | Up to 100 recipes                                                                  |
| `settings.optimizationRecipes` | `[]`                      | Up to 100; see [media](media.md)                                                   |

A provider's `kind` is `openai`, `anthropic`, `zai`, `deepseek`, `qwen`, `gemini`, `openrouter`,
`meta` or `local`; a new `meta` provider starts with the model `muse-spark-1.3`. `endpoint` is an
HTTPS URL without a user name or password; `http` is accepted only for `localhost`, `127.0.0.1` and
`[::1]`. `model` is the model ID. `allowContent` is a display preference: it never grants data
access. `effort`, `minimal` or `low` for `meta`, sets how long the model reasons; left out, the API
reasons as it does by default, and a kind that takes no effort is refused one
([reasoning effort](agents.md#add-a-model)). `segmentation`, for `local` only, names the SAM model
the server also answers on `/responses`, such as `sam-3.1`, and a laser-job check outlines features
with it ([outlines](fabrication.md#outlines)); any other kind is refused one. Keys are saved in
Settings, never in this file.

A recipe is
`{id, name, kind, formats, recursive, instructions, template, data, providerID?, shortcut?}`:

| Field          | Values                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `kind`         | `batch-rename`, `book-name`, `rename`, `organize`, `summarize`                                                                                               |
| `formats`      | Up to 100 lowercase extensions without dots; `[]` is every format                                                                                            |
| `instructions` | Up to 12,000 characters                                                                                                                                      |
| `template`     | `batch-rename`: `{name}`, `{extension}`, `{number}`; `book-name`: `{year}`, `{authors}`, `{title}`, `{publisher}`, `{extension}`; other kinds leave it empty |

The built-in recipes are **Batch rename** (`batch-rename`), **Rename as book** (`book-name`,
`{year}, {authors}, {title}, {publisher}{extension}`), **Rename with instructions** (`rename`),
**Organize files** (`organize`) and **Summarize** (`summarize`). `{extension}` includes the dot. A
recipe's data level is what it requests; the person's own approval in Settings must cover it.

Shown in **Settings → Shortcuts** and **Settings → Navigation**. Default keys are in

A shortcut is ⌘ or ⌃, optional ⌥ and ⇧, and one key: a character, `Enter`, `Backspace`, `Delete`,
`Escape`, `Space`, an arrow or `F1` to `F24`. Write it as `Cmd+Shift+K`; `Command`, `CmdOrCtrl`,
`Control`, `Option` and `Return` are read too. A key may belong to one command only, including
recipe and custom-action shortcuts and the prefix.

A binding names a line, a list of up to 20 lines run in order, or a map of further keys, at most
four deep. Keys are written as a character (`%`, `C`), a named key (`Space`, `Enter`, `Tab`, `Left`,
`F5`), with `Ctrl+`, `Alt+`, `Cmd+` or `Shift+`, or as tmux (`C-b`, `M-h`) and vim (`<C-b>`,
`<Space>`) write them.

## Profiles and workspace choices

A profile is a named set of presentation values applied at once. It is not a separate data profile
or an access grant. A window resolves the shared settings, then its workspace's default profile,
then a chosen profile, then its own local choices. Folder overrides refine browsing after that.
**Workspace look…** changes one workspace; Settings changes shared values.

```jsonc
{
  "id": "reading",
  "name": "Reading",
  "values": {
    "ui.space.minimap": false,
    "settings.editor.fontSize": 20,
    "settings.editor.wordWrap": true,
  },
}
```

| Item     | Rule                                                                                                                                                                                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`     | Lowercase letters, digits and `-`, up to 100; `focus`, `present` and `full` are reserved                                                                                                                                                                              |
| `values` | Up to 100 paths from `ui.sidebar`, `ui.titlebar`, `ui.space`, `ui.list`, `settings.appearance`, `settings.browsing` (except `restoreSession` and `confirmTrash`), `settings.editor`, `settings.terminalFont`, `settings.tiling`, `settings.tour` and `settings.theme` |
| Built in | **Focus** hides the title bar, navigation, space toolbar, minimap, viewcube and grid; **Present** also hides plane headers; **Full** shows them all, with every plane toolbar button                                                                                  |
| Commands | **Profile: _name_** applies one; **Leave profile** puts back what it replaced; **Focus mode** (**⇧⌘F**) toggles **Focus**                                                                                                                                             |

A missing profile keeps its reference and shows a diagnostic; it never rewrites the shared
configuration. Profiles cannot hold credentials, provider permissions, agent scopes or process
authority.

## Personal backups

**Workspace → Backup and Restore…** reads and writes a `.viewer-backup.json` file in the
`viewer-personal-backup` format, version `1`. It is readable JSON of at most 64 MiB (67,108,864
bytes), formatting included. Export creates a new file and never overwrites an existing one.

| Part        | Contents                                                                                                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspaces  | The saved workspace state                                                                                                                                                                                                    |
| Documents   | Up to 2,000 notes and checklists, 2,000 unsaved text buffers, 1,000 media editing drafts, 1,000 conversations and 1,000 command receipts                                                                                     |
| Preferences | Optional: `appearance`, `browsing`, `folders`, `editor`, `terminalFont`, `tiling`, `tour`, `theme`, `themes`, `profiles`, `layouts`, `shortcuts`, `keymap`, `savedSearches`, `recipes`, `optimizationRecipes` and `toolbars` |
| Never       | Original files, caches, model credentials, provider permissions, agent grants, custom actions, terminal profiles, browser cookies, live terminal sessions and server processes                                               |

Import assigns new identities and adds independent workspaces, up to the limit of 30 workspaces in
all. It refuses a backup from a newer Viewer and symbolic-link inputs, validates the whole file
before creating anything and writes only new private records. Existing documents and the backup are
kept. If writing fails partway, the records already written are kept for recovery; nothing removes
them.

Relinking rewrites typed file and folder references; document text, commands and web addresses stay
as written. Shared project associations and external agent connections need reconnecting. A restored
conversation is stopped and its saved context scopes are cleared. A command receipt that was running
becomes interrupted.

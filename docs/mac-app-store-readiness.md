# Mac App Store readiness

Assessed October 13, 2026, for Viewer 0.1.0, Apple Silicon, macOS 13 or later. **Not ready for public Store submission yet.** Build `2026101316` completed automated qualification, including 321 tests, all 11 packaged workflow groups, a 94-case preview corpus and the full signed 120 awake minute soak. Local hardening, a signed MAS development baseline and release tooling are implemented; mandatory native acceptance, file-provider coordination engineering and distribution assets remain gates. The [qualification ledger](release-qualification.md) and [verification record](verification.md) bind results to immutable candidates. The [October 12 audit](release/audit-2026-10-12.md) is historical and includes findings that have since been fixed.

## Implemented and locally checked

- Native volume inventory no longer requires a blanket `/Volumes` permission. File/folder browsing still requires the appropriate native grant. Cancelled volume pickers retain the dialog.
- Lifecycle boundaries drain or cancel readers, previews, index work, watches, subprocess preparation, terminals and handoffs before access is released. Private document writes are serialized, atomic and directory-synced. Native watches stay bounded under the 512-descriptor regression.
- Native clipboard/drag capabilities use bounded, revocable session permissions instead of filling the 128-entry persistent picker list. Saved unavailable locations are identified and can be repaired in Settings.
- Revocation prevents unchanged native clipboard/drag selections from reimporting the removed capability during background discovery. A fresh native selection or picker grant can authorize it again. Delayed canonical reads and native imports recheck the live permission rather than approving a released scope. Focused regressions cover these races; genuine picker/Finder revocation remains a native acceptance gate.
- Preview revocation/eject cleanup affects the chosen root, including canonical aliases, companion assets and archive children. Independent resources and cached thumbnails remain usable. Affected viewers abort and dispose decoded text/media/GPU state immediately. The original packaged cross-root failure and a real Settings/preview UI regression pass after the correction.
- Streamed copies guard source identity and length. macOS metadata copying covers modes, xattrs, resource forks, ACLs and relative links. Private staging checks ownership before cleanup. Durable operation receipts support guarded Undo for copies/creates and Viewer Trash, including cold relaunch. Interrupted mutations are retained for inspection rather than replayed automatically.
- ZIP creation and bounded ZIP/TAR/TAR.GZ extraction are operation jobs with progress, cancellation, collision choices and eligible Undo. Unsafe paths, conflicting names, links/special entries and size bombs are rejected.
- Unavailable native clipboard items no longer block unrelated navigation. Background discovery clears stale copied items; an actual Paste still reports access failures.
- CAD surface measurement refreshes camera/model matrices before raycasting, so a pick does not depend on the first GPU frame already having rendered. Before/after regressions and a minimized packaged first-frame reproduction cover the timing failure found during qualification.
- Model requests require explicit private approval for the provider endpoint and data level before filenames or text are transmitted. Configuration changes and Viewer’s agent API cannot grant it. Endpoint changes, revocation and key removal invalidate/cancel requests. Permissions and Privacy are available in Settings.
- Both macOS editions declare the purpose of connecting to configured LAN model endpoints, and qualification checks the description in the actual bundle. This declaration does not grant macOS local-network permission; genuine allow/deny/retry behavior remains pending. [Apple local-network guidance](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).
- Actual signed MAS PTY command/output/exit, generated child disposal and separate signed authenticated/denied MCP clients have native acceptance tests. The packaged PTY compatibility patch changes only the copied node-pty source and is rebuilt for Electron.
- The qualification runner builds/freezes exact candidates, verifies signatures and minimum OS, hashes source and bundles, inventories native binaries, runs both-channel checks and a configurable two-hour signed soak. The final two-hour check completed 239 watch/read/save cycles and 48 rendered STL cycles, with 61–62 handles and four owned processes throughout; source/bundles stayed unchanged and owned candidate/image cleanup was verified. Evidence and gates remain explicit; a passing automated run is not Store approval.
- Generated notices include 151 declared production packages, Electron/Chromium and CAD dependencies. Both production and build dependency advisory checks currently report no known advisories. This is not a security certification or a legal determination of redistribution obligations.

## Privacy and runtime inventory

Ordinary browsing/previews/indexes are local. User-configured model requests and external executables/agents are separate data flows. Do not infer “Data Not Collected” from a lack of analytics. Reconcile final App Privacy answers with actual provider processing. Explicit third-party AI consent is part of Apple's review requirements. [App Privacy guidance](https://developer.apple.com/app-store/app-privacy-details/), [Review Guidelines](https://developer.apple.com/app-store/review/guidelines/#data-use-and-sharing).

The candidate inventory includes native helpers, node-pty/spawn-helper, Electron/Chromium frameworks and WASM preview dependencies. Apple documents required-reason APIs for iOS, iPadOS, tvOS, visionOS and watchOS; the current page does not list macOS. That does not justify inventing empty manifests or ignoring applicable SDK/review declarations. Final binary requirements and App Store Connect validation remain authoritative. [Required-reason API guidance](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api), [manifest placement](https://developer.apple.com/documentation/bundleresources/adding-a-privacy-manifest-to-your-app-or-third-party-sdk).

Electron 44 requires macOS 13 or later; native helpers match the runtime minimum. Intel and later roadmap features are outside the initial release. A development-signed MAS bundle, an ad-hoc direct bundle and a distribution-signed/notarized installer are different artifacts. [Electron 44](https://www.electronjs.org/blog/electron-44-0), [MAS submission guide](https://www.electronjs.org/docs/latest/tutorial/mac-app-store-submission-guide).

Keep every unresolved critical/major defect and every unverified mandatory native scenario blocking. Use [native acceptance](release/native-acceptance.md) and the exact candidate report before approving a public release. No public publishing or submission is authorized by a passing local check alone.
